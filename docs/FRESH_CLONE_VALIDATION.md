# Verification from a fresh GitHub clone

The public repository was cloned from GitHub at
`3fee52fdab52f91026f135a71a83cc45decabaec`. Both environments below were created
separately; no existing Python site-packages were reused. The corrected release
retains the tested inference sources, configurations, and recorded raw results.
Datasets and checkpoints were supplied separately from the author's local data.

## Installation issue found and corrected

The initial Python 3.12 venv recipe installed successfully. All sixteen tests,
twenty-three YAMLs, three shell scripts' syntax, documented aggregations, and
184 public file checksums passed. All 42 recorded full runs were reported with
unchanged values, and the depth PNG was regenerated byte for byte. All 75,000
required ImageNet-C paths resolved using the metadata shipped in Git.

Actual GPU execution covered all twelve ordered-depth YAMLs (including optional
10% points), twelve architecture/settings profiles, and five CIFAR profiles.
There were 31 successful evaluator executions and 15,576 predictions. Depth
smoke checks used two corruptions and 136 images each, exercising batches of
128 plus a final eight and corruption resets. Other smoke checks used one
corruption and 136 images. Two additional ImageNet executions within these 31
covered all 5,000 Gaussian-noise images at 50% depth.

That venv did **not** reproduce the recorded ImageNet errors. The measured
Pillow 10.2 binary uses IJG JPEG 9; the tested PyPI wheel of the same version
uses libjpeg-turbo 3.0.1. On eight identical Gaussian-noise JPEG files,
1,076,783 of 1,204,224 decoded RGB elements differed. CUDA/BLAS binaries also
differed. Matching compressed-file checksums and Python version numbers did
not guarantee the same inputs or binary runtime.

The recommended installation now fixes 90 official Conda package builds and
23 tested Python additions:

```bash
conda create --name actta --file environment-conda-linux-64.lock.txt --yes
conda activate actta
python -m pip install -r requirements-depth-sweep.txt -r requirements-conda-extras.lock.txt
python tools/check_environment.py
python -m unittest discover -s tests -v
```

This recipe was executed in a new environment. Dependency checks and all
sixteen tests passed. The runtime preflight accepted it and rejected the tested
PyPI runtime. Decoded pixels on the eight-image probe matched the measured
environment bitwise. The native CUDA PyTorch, cuBLAS, and JPEG library files
also matched the existing measured environment byte for byte.

## Numerical spot checks

These are **Gaussian-noise severity-5 errors on 5,000 images**, at 50% ordered
depth and batch 128. They are not the mean errors over all fifteen corruptions.
Both models used physical GPU 3 and the unchanged LR 0.0025/frozen-affine profile.
All 5,000 image-order/content hashes, selected layers, and trainable parameters
matched the archived measurements.

ViT exactly reproduced its recorded corruption error. RN50's locked-environment
result differed by three predictions; rerunning in the existing original
environment also differed by one prediction. The cause of that remaining small
variation was not isolated. The original `cudnn_benchmark=True` is retained;
no deterministic-kernel guarantee is claimed. No measured result was replaced
and no settings were tuned to remove this difference.

The full fifteen-corruption depth sweep was not repeated during this consumer
verification. Existing full-benchmark records remain unchanged. This validates
installation, execution, aggregation, and the tested runtime's numerical spot
checks; it does not certify every published mean or three-seed paper statistic.
